## 2. research 主流程：一条任务怎样变成实验记录

```text
四份TOML → evaluation/__main__.py → load_config/load_run
 → loader读资源包与选题 → prepare复制本trial资料
 → environment.factory/start → dataset.setup
 → harness.runner.run_agent → 模型与工具循环
 → dataset.evaluate返回Score → environment.destroy
 → result/summary、原生评分、产物、trace、模型用量账本
```

dataset 配置选择任务、资源包和适配函数；environment 配置选择运行环境及启动清理预算；agent 配置选择模型、凭据变量、harness、工具和 Agent 预算；evaluation 配置选择 Skill 条件、重复次数、评分函数和通过阈值。

Task 是题目及来源，PreparedTask 是本次准备的副本，TrialContext 绑定任务与环境，AgentResult 记录作答过程，Score 记录奖励及数据集指标。一个 trial 是一道题、一个条件、一次独立运行；一次 trial 内可能请求模型很多次。--plan 只预览；真正运行还要准备环境、请求模型、评分并清理。

本机：Windows PowerShell → WSL Ubuntu 中的 research/OpenHands → Thingo 远程模型生成决策 → 本机 Docker 执行工具代码。模型请求和本地代码执行是不同环节。

原 SkillGenBench 四配置分别是 config/datasets/skillgenbench.toml、config/environments/skillgenbench.toml、config/agents/openhands-skillgenbench.toml、config/evaluation/skillgenbench.toml。新 AppWorld 使用同目录对应 appworld/openhands-appworld 文件。

SkillsBench 的3d-scan-calc用于共同上手：此前完成资源包读取与任务准备，未调用模型做该示例，不计作方向二正式样本。
